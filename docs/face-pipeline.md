# 人脸核验流水线

## 流程

```
OV2640  ──DVP──►  esp_camera  ──► 帧缓冲(PSRAM)
                                      │
                                      ▼
                          human_face_detect()      检测，返回 bbox
                                      │
                                      ▼
                          对齐 + 裁剪 + 归一化
                                      │
                                      ▼
                          esp_face_detect 特征提取
                                      │
                                      ▼
                      1:N 比对（距离阈值 + 最近邻）
                                      │
                        ┌─────────────┴─────────────┐
                        ▼                           ▼
                   命中 < 阈值                  未命中
                   xSemaphoreGive              UI 提示重试
```

## 性能构成

单次核验 < 400ms 的拆解（ESP32-S3 @240MHz，QVGA 输入）：

| 阶段 | 耗时 | 占比 |
|---|---|---|
| 抓帧 | 30–50ms | 12% |
| 人脸检测 | 150–200ms | 48% |
| 特征提取 | 90–120ms | 28% |
| 1:N 比对（20 人） | 20–40ms | 8% |
| 其他 | < 20ms | 5% |

**检测占了大头**，所以优化重点在降低检测频率：连续帧之间跟踪上一帧的 bbox，如果人脸位置变化不大就跳过检测、只做特征提取。这一项把持续识别的平均耗时压到了 200ms 以下。

## 1:N 比对

20 人库不做索引，直接线性比对全部特征向量：

```c
int best_id = -1;
float best_dist = FLT_MAX;

for (int i = 0; i < face_db_count; i++) {
    float d = cosine_distance(feat, face_db[i].feature, FEAT_DIM);
    if (d < best_dist) {
        best_dist = d;
        best_id   = i;
    }
}

if (best_dist > THRESHOLD) return -1;   /* 认不出 */
return best_id;
```

库规模上到几百人才需要做聚类或哈希索引，当前线性比对 20–40ms，完全够用。

阈值用实测标定：同一人不同光照/角度的类内距离分布，与不同人之间的类间距离分布，取两条分布的交点略偏保守侧。

## 误识率控制

20 人库，不同光照条件下统计：

| 条件 | 误识率 | 拒识率 |
|---|---|---|
| 正常室内光 | < 1% | 2% |
| 侧光 / 逆光 | < 3% | 6% |
| 戴眼镜 | < 3% | 5% |
| 戴帽子 | — | 大幅上升（不入库） |

**误识率的代价是不对称的**：把陌生人认成已注册用户（误识）比把本人拒掉（拒识）严重得多。所以阈值往保守侧调，宁可让用户多试一次，也不能放错人。

## 人脸库持久化

```c
/* 注册 */
esp_face_detect_set_ids_from_flash();     /* 启动时从 Flash 加载 ID 表 */

/* 更新 */
face_db_add(id, feature);                 /* 内存 */
face_db_flush();                          /* 落 Flash，掉电不丢 */

/* 云端增量更新 */
mqtt_on_message -> face_db_update(id, feature) -> face_db_flush();
```

支持通过 MQTT 下行指令**增量更新单条人脸数据**，不需要返场刷机，也不需要重刷整个固件。

## 调试经验

| 问题 | 现象 | 根因 | 解法 |
|---|---|---|---|
| 抓拍帧花屏 | 预览图像错位 | 帧缓冲被复用 | 帧队列深度 2 + 引用计数，用完才 release |
| 识别时 UI 卡 | 触摸延迟明显 | 推理与 UI 同核 | 绑核分离 |
| 误识偏高 | 双胞胎/相似脸误认 | 阈值过宽 | 收紧阈值，接受拒识率上升 |
| 首次核验慢 | 第一次 800ms+ | 模型首次加载到 PSRAM | 开机预热跑一次空推理 |
